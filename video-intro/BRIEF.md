## Intent

面向 GitHub 上打开 `csuft-auto-checkin` 仓库的访客 —— 主要是有一定技术基础、
想自己部署一套的同学或开发者。他们需要在一支片子里搞清楚三件事：这工具到底
做什么、怎么把它跑起来、以及有什么风险。

语气要**克制、诚实、不推销**。这个项目本身涉及"代打卡"的合规争议，所以片子
开场就必须把免责声明完整讲清楚，而不是藏在最后。宁可显得保守，也不要让人
误以为这是什么"稳过"的作弊工具。

观看场景是 GitHub 项目主页 / README 内嵌，所以：**无声、无旁白，全靠字幕与
画面自己讲**。观众很可能在静音状态下扫一遍，因此每个画面的信息密度要够，
但也不能靠快速闪现 —— 字幕要读得完。

视觉上走技术文档 / 终端风格：等宽字、清晰的信息层级、示意图而不是装饰性
插图。要有一点点音效做节拍，但不能吵。

## Assets

无外部素材。所有视觉由 Step 4-5 现场构建（排版、示意图、数据可视化）。
仓库内的 README / DISCLAIMER / DEPLOY 文档作为**信息源**，不是素材。

## Customizations

- **完整免责声明**：用户明确要求免责声明"要完整"，不接受一句话带过。
  必须覆盖：代打卡可能违反校规、坐标不代表真实位置、按现状提供不担保、
  作者与学校无关联、使用者自负后果。
- **无旁白**：不做 TTS、不需要 SCRIPT.md。
- **字幕**：作为主要信息载体，必须有，且要读得完。
- **轻音效**：转场与关键点上的点缀音，音量克制。
- **横屏 16:9**：1920x1080。
- **约 2 分钟**：四段结构大致 25s / 40s / 40s / 15s。

## Notes

- 内容顺序**固定**：①免责声明 ②功能与用法 ③本地/云部署 ④AI 辅助部署。
- 片中出现的所有命令、路径、参数必须与仓库真实内容一致，不能编造。
- 不要出现任何真实学号、姓名、服务器 IP、token —— 仓库本身就是脱敏过的。
- 不要吹嘘"保证签到成功"：真实情况是接口可能变更、学校可能调整规则。
- 可以提到项目的技术亮点（签名算法复刻、会话滚动续期、状态码判定），
  但要用"实现了什么"的陈述语气，不做营销式渲染。
- 免责声明段落的画面不要用警示红黄那种吓人的配色，用预设本身的克制色，
  靠排版层级和留白表达严肃。
